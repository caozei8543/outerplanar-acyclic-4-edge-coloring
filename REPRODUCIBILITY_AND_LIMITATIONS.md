# Final-version reproducibility contract and limitations

1. **Single canonical article:** the 17-page PDF in `paper/`; its SHA-256 and page count are in `MANUSCRIPT_VERSION.json`. No 23-page draft, older 339/656 counts, or speculative, non-measured performance curves belong in this release.
2. **Finite-state mathematics:** palette `{1,2,3,4}`; terminal sets use four bits; pair bits order `12,13,14,23,24,34`; full/exposed state bounds 16,384/956; antichain upper bound 468; orbits 82. Integer calculations are exact, while formal bounds are not observed retained-state counts.
3. **Algorithm:** the three variants share binary series/parallel decompositions and original color labels; `Exposed=project(Full)` and `Dominance=minimize(Exposed)` are tested at each reported node. An independent graph coloring verifier checks reconstructed output, not merely the DP's own state masks.
4. **Exact test suite:** 649 benchmark entries = 332 Graph Atlas + 5 selected maximal examples + 200 nonmaximal + 100 multiblock generated + 12 Q/deletions. Within each synthetic group/order isomorphism is checked; between groups duplicates are permitted. The 332 Atlas and 12 Q cases have an independently coded exhaustive oracle. Overall results: 331/1 Atlas, 11/1 Q, zero recorded disagreements. Q matches Graph Atlas G840.
5. **Experimental run protocol:** one warm-up, seven measured repetitions and median per instance/mode; pooling 40 nonmaximal + 20 multiblock per order, unweighted average across graphs. Only DP `run_tree` is timed. Decomposition, correctness tests and memory tracing are excluded. Memory uses separate `tracemalloc` peak, decimal MB; it is **not RSS**. Platform/run metadata are in `run_manifest.json`.
6. **Final Figure 6:** measured archived n=192 pooled reduction 13.68% states and 13.21% traced peak; time rises from 20.68 to 38.09 ms. Unlike some earlier draft, it does **not** claim speedup. Graph generation choices are in `benchmarks.py`; timing is platform-dependent.
7. **Hardware metadata boundary:** archive manifest specifies Linux/Python/NetworkX, not the laptop CPU/RAM described in the final manuscript. We have not rewritten manifest hardware fields to match the final PDF. That hardware claim needs a separate author-held record if strict provenance is required.
8. **Complexity boundary:** `dp.py` has O(number of given binary SP decomposition nodes) for fixed four colors. `decomposition.py` uses repeated reductions and can have superlinear preprocessing. This is compatible with the conditional complexity assertion in final Proposition 18; it does not demonstrate a complete optimized linear-time program.
9. **Figure 7:** combinatorial Q color/deletion facts and the five-color witness are directly checked. The campus IoT scene is an illustration, not a field-trial record.
10. **Figure 8:** the 71 labeled nodes and 76 drawn edges were **manually transcribed from the final PDF image** into `figure8.py`. Code verifies its outerplanarity, Δ=4, cycle rank 6 and an independently computed acyclic 4-slot schedule. **The generated witness may use different colors than the edges in the raster figure.** Since the original input edge/slot file was not supplied, a precise original-slot-file provenance claim remains unavailable. The topology is deployment-inspired, not field-measured.
11. **Mathematical proof boundary:** enumeration, input/output correctness and test coverage do not prove the general contextual equivalence theorem or priority/novelty of Q. The PDF itself contains the mathematical proof and appropriately cites prior work. No forbidden-subgraph characterization for arbitrary outerplanar maximum-degree-four graphs is claimed.
12. **Copyright and attribution:** MIT applies to original software/docs in this package, not automatically to the attached PDF/figures. Before publishing the public GitHub release, check article and image permissions; distribution of a local submission reference does not itself grant publisher reuse rights.
13. **Reproducibility commands:** install with `pip install -e '.[plot,test]'`; run `pytest`, `scripts/verify_paper_alignment.py`, `scripts/verify_figure8.py`, `scripts/verify_release.py`; regenerate timing only to a new local directory. SHA-256 checks fail after any intentional edit until a *new* release manifest is generated.
